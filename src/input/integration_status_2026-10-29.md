# 처방 모듈 통합 점검과 담당 정리 (2026-10-29)

작성: 담당 A. 받는 사람: B, C, D.

VC-0103 한 건을 A → B → C·D 검색 → B `recommend()`까지 이 PC에서 돌려 보고 정리했다 (커밋 `014e34b` 기준, 이후 main의 PR #78~#80 반영 내용은 표에 적음, 급여 청크는 공고책자 2026-11-01 제2026-232호를 `--offline --no-llm`으로 만듦).
마지막 절에는 이 프로젝트(mini)와 다음 프로젝트(`team_project_final`의 `docs/research_datasets_models.md` v6.1) 모듈이 유방암 치료 과정의 어느 단계를 돕는지 적었다.

## 1. 구동 순서별 점검 결과

| 순서 | 모듈 | 결과 | 문제 |
|---|---|---|---|
| 1 | A 입력 `run()` → `patient_state` | 동작. 규칙만 쓰면 다섯 세트 모두 100%, qwen3:14b로 처음 보는 사례에서 틀린 칸 5개 (`llm_performance.md`) | 임상 종양 크기·초음파 소견 인용을 자주 놓침 |
| 2 | B 바이오마커 `assess()` → `biomarker_record` | 동작. VC-0103 HR+/HER2-, metastatic 1L, 스키마 오류 0 | 없음 (gBRCA 생식세포 칸 우선은 2026-10-29 B 반영, PR #78) |
| 3 | 화면 1 → `confirmed_state` | **만드는 코드가 없음.** VC-0103만 손으로 만든 파일이 있음 | 아래 1.1 |
| 4 | C 지침 검색 `retrieve_for_recommend()` | 동작. 질문 세트 29문항 문서 100%, 소단원 100%, recall@5 0.91, MRR 0.97. VC-0103 정답 청크 1위 | 청크 `drugs` 목록에 계열 이름(AI)으로 쓴 약이 없음 (아래 1.2) |
| 5 | D 급여 청크 → C 급여 검색 | 청크 156개 (검사 모두 통과), 색인 131개, VC-0103 급여 행 17개 (간주 차수 2L 포함) | 투여 조건 구조화가 비어 있음 (아래 1.3) |
| 6 | B 추천 `recommend()` | 가짜 LLM 답으로 후처리·형식 검사 동작. `fulvestrant + palbociclib` → 급여(조건 확인 필요), 형식 오류 0 | `llm/config.toml`에 `[recommend]` 칸이 없어 실제 LLM을 붙이면 멈춤. 입력이 아직 `patient_state` + `biomarker_record` |
| 7 | 전체 연결 | 차트 한 건을 넣어 추천까지 한 번에 돌리는 진입점이 없음 | 이번 점검도 임시 스크립트로 함 |

### 1.1 검색은 `confirmed_state`를 거쳐야 맞다

같은 VC-0103(보조 AI 투여 중 12개월 안에 재발)으로 두 방식을 비교했다.

| 검색 입력 | 1위 지침 청크 | 맞는가 |
|---|---|---|
| `confirmed_state` | `esmo-mbc-2026-05-luminal-1l-0fd38a` (Fulvestrant + CDK4/6, 보조 ET 중·12개월 이내 재발) | 맞음 |
| `patient_state` + `biomarker_record` (옛 방식) | `esmo-mbc-2026-05-luminal-1l-02649c` (AI + CDK4/6, 보조 ET 종료 12개월 뒤 재발) | **틀림** |

옛 방식(`patient_from_state`)은 `endocrine_relapse_12m`을 채우지 않는다. 그래서 2단계는 `confirmed_state`만 받아야 한다 (`handoff_confirmed_state_to_B.md` §1).
C는 이미 바꿨고, B의 `recommend()`와 `confirmed_state`를 만드는 코드가 남았다.

### 1.2 계열 이름으로 쓴 약이 후보에서 지워진다

ESMO는 "AI—CDK4/6 inhibitor"처럼 계열 이름으로 쓴다. 청크 `drugs`에는 letrozole·anastrozole·exemestane가 없다 (이 셋이 든 청크 2개, `drugs`가 빈 청크 174개 중 72개).
B 후처리 3번 규칙(인용 청크에 없는 약 이름이면 후보 삭제)이 `letrozole + palbociclib`을 지운다. 급여 검색은 같은 조합의 1차 행(`bc-pal-endo-1l-r01`)을 찾는데도 지운다.
VC-0103에는 맞지 않는 처방이라 결과는 같지만, 보조 ET 종료 12개월 뒤 재발한 HR+ 환자에게는 표준 1차 처방이 사라진다.

### 1.3 급여 분류가 확정되지 않는다

`--no-llm`이라 조건 131개가 비어 있다. B의 판정기(`conditions_eval.py`)는 있지만 판정할 조건이 없어 모든 후보가 "급여(조건 확인 필요)"로 남는다.
조건 구조화는 아직 Claude API나 `claude -p`를 쓰고, 로컬 LLM은 정하지 않았다 (PROJECT.md §14).

## 3. 빠진 부분과 담당 제안

| 빠진 부분 | 담당 제안 | 이유 |
|---|---|---|
| `recommend()` 입력을 `confirmed_state`로 | B | 10-21 전달 문서 §4-2. C는 바꿨고 B만 남음 |
| 추천 LLM 연결 (`[recommend]` 칸, 모델 선정) | B | 10-21 전달 문서 §4-1. 입력 모듈 모델(`[extract]`, qwen3:14b)과는 별개 |
| 계열 이름 약 맞추기 | C 주담당, B 확인 | 청크 `drugs`는 C 형식. 청크에서 풀면 후처리·급여 검색·프롬프트가 함께 맞음. B 후처리만 고치면 다른 곳에 같은 구멍이 남음 |
| `confirmed_state` 기본값 만들기 (`patient_state` + `biomarker_record` → `confirmed_state`) | A | 스키마를 A가 설계했고 칸 대부분이 A 값 (`deemed_lines`, `endocrine_relapse_12m`, 차수, 판정 기준일 값). `biomarker_record`는 스키마 형식으로만 읽음 |
| 화면 1 (의사 확정 화면) | 팀 결정 | 최종 출력 형식이 미정 (PROJECT.md §14). 정하기 전에는 기본값을 확정값으로 씀 |
| 전체 실행 파일 (차트 → 추천) | A, 둘 폴더는 팀 결정 | §15.4 A의 2단계 일 ("가상 차트를 전체 흐름에 넣어 끝까지 돌린다"). 각 모듈의 공개 진입점만 부름. `src/input/`에 두면 다른 모듈을 부르게 되므로 `src/app/` 같은 공용 위치가 필요 |
| 급여 조건 판정 확정 | D 조건 구조화, B 판정기 | 판정기는 있음. 조건 데이터가 비어 있음 |
| `dfi_days`·`high_risk_early` 계산 위치 | A 또는 B (10-21 전달 문서 §6-5, 미정) | 차수·간주 규칙을 A가 계산하므로 A가 자연스러움 |

먼저 할 순서: ① `confirmed_state` 기본값 (A) → ② 계열 이름 약 (C) → ③ `recommend()` 입력·LLM 연결 (B) → ④ 급여 조건 (D) → ⑤ 전체 실행 파일 (A, 위치는 팀).

## 4. 유방암 치료 과정에서 각 모듈이 돕는 일

mini는 이 저장소의 [1]~[5]이고, final은 다음 프로젝트(`team_project_final`) 계획의 모듈 1~4다.
final 모듈은 H&E 슬라이드에서 예측하고, mini 모듈은 차트·지침·급여 기준으로 처방 후보를 만든다.
두 프로젝트는 서로 다른 저장소이고, 아래는 같은 치료 과정에 놓았을 때의 위치다. 지금 두 프로젝트를 코드로 연결하지는 않는다.

| 단계 | 진료에서 하는 일 | 돕는 모듈 | 무엇을 돕나 |
|---|---|---|---|
| 1. 진단 (생검) | 바늘 생검으로 암 확인, H&E 판독 | final 3 바이오마커 예측 | H&E만으로 ER·PR·HER2·Ki-67을 먼저 짐작하고, IHC 결과와 다르면 재확인 표시 (병리 QC) |
| 2. 병리·바이오마커 판정 | IHC·ISH·유전자 검사 결과로 아형 결정 | mini [1] 입력, [2] 바이오마커 | 차트 원문에서 검사값을 근거 위치와 함께 뽑고 (A), 규칙으로 HER2-low·아형·검사 공백을 판정 (B). 빠진 검사(gBRCA, PIK3CA 등)는 검사 권고로 냄 |
| 3. 수술 계획 | 병기 판단, 겨드랑이 수술 범위 결정 | final 2 림프절 전이 예측 | 생검 H&E로 림프절 전이 위험(N0 / 1–2개 / 3개 이상)을 예측해 추가 검사·수술 범위 참고 |
| 4. 수술 후 보조요법 결정 | 항암 여부, 내분비·표적 치료 선택 | final 1 재발 위험, mini [3]·[4]·[5] | final 1: Oncotype DX 대신 H&E로 재발 위험 점수를 짐작해 항암 필요성 판단을 도움. mini: ESMO 조기 유방암 권고와 심평원 급여 기준으로 보조요법 후보와 급여 분류를 냄 |
| 5. 추적 관찰 | 재발 감시 | mini [1] | 재진 차트에서 재발일·재발 부위·치료 경과를 시간 순서로 정리해 다음 결정의 바탕을 만듦 |
| 6. 재발·전이 진단 | 재생검, 수용체 재확인 | mini [1]·[2] | 재생검 결과를 원발보다 앞세워 판정하고 (IN-4), 원발 대비 바뀐 수용체를 이유에 적음. ESR1 재검 등 검사 공백 권고 |
| 7. 전이성 차수별 치료 | 1차·2차·3차 이상 치료 선택 | mini [2]·[3]·[4]·[5], final 4-B (옵션) | mini: 내분비·항암 차수를 따로 세고, 심평원 간주 규칙(보조요법 중 재발 → 1회 간주 등)을 반영해 ESMO 권고와 급여 행을 함께 찾고, 문장마다 근거 청크를 단 처방 후보와 급여 분류를 냄. 이 프로젝트가 가장 많이 돕는 단계. final 4-B: 비슷한 과거 환자가 받은 치료·경과를 참고 사례로 보여줌 |
| 8. 투약과 부작용 관리 | 투약 전 상담, 부작용 대처 | final 4-A (옵션) | mini가 낸 `recommendation.json`의 약 목록을 받아 약 라벨 근거로 부작용을 쉬운 말로 설명하고, 유전형(DPYD 등)에 따른 위험을 경고 |
| 9. 급여 기준 변경 반영 | 새 공고 시행 | mini [5] | 심평원 개정 공고를 시행일 기준으로 책자에 겹쳐 반영하고 화면 하단에 반영 현황을 보여줌 |

정리하면 mini는 2·5·6·7·9단계(검사 판정, 경과 정리, 차수별 처방 후보, 급여)를, final은 1·3·4단계(진단 직후 H&E 예측)와 7·8단계 옵션(유사 환자, 부작용)을 돕는다.
mini의 가상 차트가 전이성 차수 결정에 집중한 것도 이 때문이다. TCGA 기반 가상 차트는 대부분 수술 후 보조요법 사례가 되어 7단계를 보여주기 어려워 만들지 않기로 했다 (2026-10-29).

모든 모듈은 의사의 결정을 대신하지 않는 참고 자료다. mini는 가상 차트와 공개 자료로만 개발하고, 실제 환자 차트 검증은 IRB 승인 뒤에 한다 (PROJECT.md §2).
