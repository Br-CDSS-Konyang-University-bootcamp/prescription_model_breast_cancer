# 입력 모듈 최종 성능 (2026-10-29)

입력 모듈(A)의 LLM 추출 + 규칙 정규화 최종 결과. 측정 코드는 커밋 `24f2181` (main), GPU 서버 Ollama.
이 문서가 옛 `llm_extraction_runs.md`(CPU 1~3차 기록)를 대신한다.

## 결론: `qwen3:14b` 선택

| 기준 | qwen3:14b | hari-q3-8b (Q4_K_M) |
|---|---|---|
| 틀린 칸 합계 (4세트) | **10** | 14 |
| 처음 보는 사례 (보류 + 표현 변형) 틀린 칸 | **5** | 10 |
| 날짜 형식 변형 15건 | **0칸 (100%)** | 6칸 (99.1%) |
| 근거 위치 정확 일치 | **79~83%** | 70~75% |
| 실행 시간 (사례 합, 초) | 834 | **578** (약 30% 빠름) |
| 크기 | 14B | 8B |

- 규칙을 맞춘 개발·시험 세트에서는 두 모델이 거의 같다 (qwen 5칸, hari 4칸).
- 규칙을 맞추지 않은 보류 세트와 표현 변형에서 qwen이 절반만 틀린다. 실제 차트에 가까운 쪽은 이 두 세트다.
- hari는 원문 인용을 바꿔 써서 위치를 못 찾는 일이 있다 (`놀바덱스` → `놀바.dex`, BRCA 변이 표기 변경). 인용이 틀리면 규칙이 값을 버리므로 치료 줄 하나가 통째로 빠진다.
- 속도는 hari가 낫지만, 한 사례당 qwen도 GPU에서 평균 13초 정도라 문제되지 않는다.

`llm/config.toml`의 `[extract]` 모델은 아직 `hf.co/mradermacher/hari-q3-8b-GGUF:Q4_K_M`이다.
`llm/`은 공용 폴더라 네 명 검토 뒤에 `qwen3:14b`로 바꾼다. 그 전에는 실행할 때 `--model qwen3:14b`를 붙인다.

## 세트별 점수

근거 위치는 출력 인용 위치가 정답 위치와 정확히 같은 비율. 인용 준수율은 출력 인용이 원문에 그대로 있는 비율.

## 남은 오류 (qwen3:14b)

| 사례 | 칸 | 내용 | 원인 |
|---|---|---|---|
| VC-0106b | Ki-67 | 정답 conflict (15%, 25%)인데 25%만 냄 | 첫 보고서의 Ki-67 인용을 놓침 |
| VC-0107 | diagnosis_date | 정답 2023-05-02인데 2023-05-14를 냄 | 진단일 대신 다른 날짜 문장을 인용 |
| VC-0119, 0121, 0124 (시험) / VC-0132, 0136, 0144 (보류) | clinical_size_mm | 임상 종양 크기 빠짐 | 영상 문서의 크기 문장을 인용하지 않음 (반복되는 약점) |
| VC-0130, 0135 (보류) | 초음파 영상 소견 | 영상 줄 하나 빠짐 | 초음파 문장 인용을 놓침 |

hari-q3-8b는 이 밖에 ECOG(VC-0108, 0127), VC-0109 전이 부위 (변형 3건 포함), VC-0126 visceral_crisis, VC-0108-yy 동반 질환, VC-0109 tamoxifen 치료 줄 (인용 변형, korean·yy), BRCA1 변이 (VC-0115-g21, VC-0135, 표기 변형)를 틀렸다.

보류 세트의 틀린 칸은 규칙·프롬프트를 고치는 데 쓰지 않는다 (`virtual_patient_cases.md` §8).
`clinical_size_mm`는 개발·시험 세트에서도 보이므로, 고친다면 그 세트의 사례로만 프롬프트 예시를 보강한다.

## 다시 재는 방법

1. GPU 서버 터널을 연다 (PowerShell 창 하나, 켜 둔 채로):

   ```bash
   ssh -p 2222 -N -L 11435:127.0.0.1:11500 team30105@221.158.65.91
   ```

   서버 주소를 `--host`에 직접 넣지 않는다. 환자 텍스트는 터널을 거쳐 서버의 로컬 모델만 본다.

2. 다른 창에서 세트마다 실행한다 (`--set`은 dev, test, holdout, variants, pairs):

   ```bash
   python -m src.input.script.pipeline --set holdout --host http://127.0.0.1:11435 --model qwen3:14b --out data/input/runs/qwen3-14b-gpu-holdout
   ```

3. 채점한다 (`--show-wrong N`으로 틀린 칸을 본다):

   ```bash
   python -m src.input.script.evaluation data/input/runs/qwen3-14b-gpu-holdout --show-wrong 20
   ```

4. 규칙만 고쳤을 때는 LLM을 다시 부르지 않고 저장된 후보로 다시 조립한다:

   ```bash
   python -m src.input.script.pipeline --replay data/input/runs/qwen3-14b-gpu-holdout
   ```

이번 결과 폴더는 `data/input/runs/<모델>-gpu-<세트>-final/`에 있다 (git에 올리지 않음).
