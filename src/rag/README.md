# [3] 지침 RAG + 공용 검색 색인 — 담당 C

ESMO 지침을 수집·청킹하고, 지침과 급여 청크가 함께 들어가는 공용 검색 색인을 관리한다.

- 범위: PROJECT.md §6
- 입력: 지침 원문 PDF, D가 만든 급여 청크
- 출력: 검색 API (setting·subtype·line 필터 + biomarker_tags 가중치 + 재정렬)
- 색인 쓰기·검색 코드는 이 폴더에만 둔다. D는 이 폴더의 색인 함수를 호출해 급여 청크를 넣는다.
- 청크 형식은 `schemas/chunk.json`을 따른다.
- 테스트: `tests/rag/`

ESMO 권고가 아예 없는 요법(megestrol, CMF 등)만이 아니라 다른 차수 권고의 약(1차 환자의 everolimus, eribulin 등)도 들어간다. 이번 결정의 치료 계열(HR+/HER2- 내분비 결정이면 내분비요법) 행이 앞, 다른 치료, 보조약 순이다. 수가 많아(VC-0103 기준 57행) 화면에 낼 때는 B의 조건 판정을 거친다. 기본값은 끔이라 B의 지금 호출은 그대로다. A·B 내부 코드는 쓰지 않는다 |

| `searcher.py` | `search_guidelines()`. `with_parent=True`면 결과마다 부모(소단원) 청크를 `parent`로 붙인다. 재정렬이 기본으로 켜져 있다(`rerank=True`, PROJECT.md §6): 뜻 검색 후보 20개(`RERANK_CANDIDATES`)를 재정렬 모델(bge-reranker-v2-m3, 처음 쓸 때 약 2GB 내려받음)로 다시 매긴다. 모델을 불러오지 못하면 경고하고 뜻 검색 점수를 쓴다. 같은 조건의 검색은 결과를 기억해 두고(최대 256개), 색인을 바꾸면 비운다. `metastatic_sites`(예: `["bone", "liver"]`, field_vocab.csv 값)를 주면 부위별 권고(뼈·뇌·연수막 전이 소단원)를 그 부위 전이가 있으면 +0.05, 없으면 후보에서 뺀다 (감점만 하면 그런 권고가 후보 자리를 채웠다). 연수막 전이는 표준값이 없어 `other: leptomeningeal …`처럼 적힌 값을 찾는다. 주지 않으면 점수를 바꾸지 않는다. 차수는 거르지 않고 점수로 반영한다: 같으면 +0.1, 청크가 `any`면 +0.03, 다른 차수만 가리키면 -1.0 (맞는 차수·any 권고 뒤로). `negative_tags`(환자가 음성으로 확인된 바이오마커 태그, `query.negative_tags(record)`가 만듦)를 주면 그 태그만 조건으로 하는 권고를 -1.0 한다 (예: gBRCA 음성 환자의 gBRCA 변이용 olaparib. 태그가 여러 개인 권고는 모두 음성일 때만). 결과의 `score`는 뜻 검색(또는 재정렬) 점수 + 차수·태그·전이 부위·음성 바이오마커 가점·감점. 개정으로 대체된 청크(`superseded_by`에 값이 있음)는 찾지 않는다 (PROJECT.md §6, 급여 검색과 같은 규칙). `chunk_kind`(기본 `recommendation`)로 찾을 청크 종류를 고른다: 알고리즘 그림 경로(`algorithm`)는 같은 권고를 그림 순서로 다시 적은 것이라 함께 찾으면 상위를 차지해 권고가 밀렸다 (평가 MRR 0.97 → 0.65, 2026-10-20). 그래서 기본 검색에서 빼고 따로 찾는다 (`chunk_kind="algorithm"`, `None`이면 모두). `endocrine_relapse_12m`("yes"/"no", confirmed_state의 확정값)을 주면 보조 내분비요법 중·12개월 이내 재발 여부가 반대인 갈래만 가리키는 권고·그림 경로를 −1.0 한다: ESMO MBC 1차의 fulvestrant–CDK4/6(12개월 이내) / AI–CDK4/6(de novo·12개월 넘어)는 이 구절만 달라 재정렬 모델이 못 갈랐다 (VC-0103 `check_case`에서 AI–CDK4/6이 1위, 2026-10-21). 두 갈래를 다 말하는 권고와 값이 없을 때는 바꾸지 않는다 |

| `reimbursement_search.py` | `search_reimbursement(drugs, setting, line, as_of)`: 추천 후보 요법(약 목록)에 맞는 급여 행(D의 L3 청크)을 찾는다. | `run_indexing.py` | `data/chunks/*.json`을 스키마 검증하고, 지침 청크만 바꿔 끼운다 (`replace_doc_type("guideline", …)`, D의 급여 청크는 남김). 실행: `python -m src.rag.run_indexing` |
| `evaluate.py` | 평가 문제집 `data/eval/rag_eval_cases.csv`로 검색을 채점한다. L0 문서(1위가 정답 문서인가), L1 소단원(상위 k개에 정답 소단원), L2 권고(hit@k, recall@k, MRR). 실행: `python -m src.rag.evaluate [--k 5] [--no-rerank] [--candidates 20] [--reranker 모델] [--auto-query] [--out 결과.csv]`. `--auto-query`는 문제집 질의 대신 환자 조건으로 만든 질의(`query.py`)로 채점한다. `--with-extra`는 주 검색 k개 뒤에 부위별·de novo 추가 검색 결과(각 3개)를 붙여 전부를 채점한다. `--query-style`은 adaptive(기본: 필터로 이미 거른 아형·병기 표현을 빼되 차수·이전 치료만 남으면 넣음), full, focused. 질의당 검색 시간도 보여 준다 (색인을 먼저 만든다). 2026-10-22 Windows 결과(29문항, k=5, 재정렬): 문제집 질의 MRR 0.97, `--auto-query` 0.88(hit 97%), `--auto-query --with-extra` 0.89(hit 100%, recall 0.98). 남은 낮은 문항은 E05(환자 정보에 고위험이 없어 질의가 E01과 같았음, `high_risk_early` 추가), M11·M14·M15(정답 범위가 좁음, 검수 대상), M17(de novo 수술 권고 7위) |
| `bench_reranker.py` | 재정렬 모델이 느린 원인을 나눠 잰다 (모델 불러오기, 후보 수, CPU 스레드 수, 최대 입력 길이). 실행: `python -m src.rag.bench_reranker [--model 이름]` |

모든 명령은 `team_project` 폴더에서 실행한다. 순서: PDF 변환 → 품질 검사 → 청커 → 알고리즘 그림 (`algorithm_esmo`, PDF를 직접 읽음) → `python -m pytest tests/rag` → 색인.

- 지침 PDF와 변환한 md(`data/parsed_md/`)는 저작권 문서라 저장소에 올리지 않는다. 각자 PDF에서 만든다. PDF는 `data/guidelines/sources.csv`에 적힌 곳(조기 2024·전이성 2026 모두 esmo.org 게시본)에서 받는다. 변환할 때 파일 지문(sha256)을 이 목록과 비교해, 다른 판이면 경고한다 (쪽 번호와 chunk_id가 판에 따라 달라질 수 있다).
- 청크 JSON은 `data/chunks/`에 커밋한다 (`.gitignore`에서 이 폴더의 `.json`만 허용). 커밋 전에 `tests/rag/test_chunks_schema.py`(스키마 검증, chunk_id 중복)가 통과해야 한다.
- chunk_id는 다시 청킹해도 바뀌지 않아야 한다 (평가셋 정답과 추천 결과의 인용이 가리킨다). ESMO 권고는 번호가 없어 첫 근거 등급 표시까지의 문장으로 만든 지문(`esmo-mbc-2026-05-luminal-2l-3f2a9c`, `chunk_common.stable_key`)을 쓴다. 순서 번호(r01, r02)는 앞에 권고 하나만 늘어도 뒤가 모두 밀리므로 쓰지 않는다. `tests/rag/test_chunk_ids.py`가 이 성질을 검사한다.
- 쪽 번호: 변환할 때 쪽마다 `<!-- page pdf=3 printed=1205 -->` 표시를 넣고 (인쇄 쪽은 PDF 정보 칸의 실린 쪽 범위에서 계산), 청커가 청크 본문을 이 md에서 찾아 `page_start`·`page_end`를 채운다. 기본은 학술지 인쇄 쪽(D의 급여 청크도 인쇄 쪽)이고, `chunk_common.PAGE_NUMBERING = "pdf"`로 바꾸면 PDF 쪽이 된다. 2026-10-19 이전에 만든 md에는 쪽 표시가 없으니 `--overwrite`로 다시 변환한다 (안 하면 테스트가 쪽 번호 없음으로 실패).
- 부모-자식 청크: 권고 청크(자식)마다 `parent_id`로 소단원 청크(부모, `chunk_kind: section`)를 가리킨다. 부모 본문은 소단원 제목 + 자식 권고 전체다. ESMO 소단원(`esmo-mbc-2026-05-luminal-2l`)이 부모다. 검색 색인에는 자식만 넣고, 부모는 JSON에 두고 `get_parent`로 찾는다 (D의 급여 청크와 같은 방식).
- ASCO 지침은 재사용 불가로 확인돼 쓰지 않는다 (2026-10-20). PDF·md·청크를 두지 않는다.
- 평가 문제집: 문항마다 질의, 하드 필터 값(setting, subtype, line), 태그, 음성 태그(`negative_tags`), 전이 부위(`metastatic_sites`)와 환자 정보(`menopausal_status`, `pcr`, `stage_at_diagnosis`, `high_risk_early`(조기 고위험 ESMO 기준 yes/no), `prior_subclasses`, `prior_classes`. 비우면 모름. `--auto-query`가 쓴다), 정답 문서·소단원·권고 ID를 적는다 (목록은 `;`로 구분). 정답은 ESMO 원문에서 고른 초안이라 `status=draft`이고, 원문과 대조해 확인하면 `reviewed`로 바꾼다 (PROJECT.md §12, 의료진 검토 없이 원문 기반). `tests/rag/test_evaluate.py`가 정답 ID가 청크에 있고 그 문항의 필터를 통과하는지 검사한다. 청크 ID가 바뀌면 이 파일도 고친다.
- 청킹하는 문서 목록은 청커의 `DOCS`에 있다. 제외한 문서와 이유는 `rag_non_prescription_docs.md`.
