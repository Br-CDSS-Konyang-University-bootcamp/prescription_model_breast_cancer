# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`prescription_model_breast_cancer`: a team Python project for a breast cancer prescription model. The repository is at an early stage. Module code goes in `src/<module>/` with tests in `tests/<module>/` (see PROJECT.md §15). TCGA data scripts live in `data/script/`. There is no dependency file or lint configuration yet. Tests run with `python -m pytest tests/<module>` from the `team_project` folder.

TCGA data scripts (run from the `team_project` conda env, from any folder; paths resolve from the script location, with `data/` as the base):

- `data/script/tcga_brca_download.py`: downloads TCGA-BRCA clinical files (GDC BCR Biotab) and cBioPortal PanCancer Atlas clinical, mutation, and biomarker-gene CNA data into `data/tcga_brca/`. Already-downloaded files are skipped.
- `data/script/tcga_brca_explore.py`: prints a structure summary and writes `data/tcga_brca/structure_report.md`. Needs `tabulate`.
- `data/script/tcga_brca_merge.py`: joins all tables on patient ID into one row per patient, `data/tcga_brca/merged/tcga_brca_merged.csv`, plus a column dictionary CSV. Multi-row tables (drugs, radiation, recurrence, follow-up, other cancers, mutations) are summarized per patient. Column prefixes name the source. Run after the download script. Drug names and therapy types are corrected with `data/dictionaries/drug_names.csv` (raw name to generic) and `data/dictionaries/drug_classes.csv` (generic to class). `drug_classes.csv` also holds default cycle lengths (`cycle_days`, `cycle_note`) per generic name, used to estimate `treatment_history[].cycles` when no cycle count is recorded, and a `drug_subclass` (anthracycline, taxane, AI_nonsteroidal, AI_steroidal, LHRH_agonist, SERM, SERD, progestin, CDK4/6_inhibitor, immune_checkpoint_inhibitor) that matches HIRA notice drug-group terms; `data/dictionaries/reimbursement_terms.csv` maps HIRA notice terms to JSON fields and values. The merge stops if a drug name is missing from the dictionary; add it there. Original values stay in `drug_*_raw` columns, and every correction is logged in `merged/drug_corrections.csv`.
- `data/script/tcga_brca_crop.py`: reads the merged CSV (unchanged) and writes `merged/tcga_brca_merging_cropped.csv`, dropping male patients and the columns listed in its `DROP` dict. It first drops patients whose overall stage is `[Discrepancy]`, `[Not Available]`, or blank (the input module's answer-set rule), then adds `stage_disease_extent` (stage I–II `early`, III `locally_advanced` per the HIRA reimbursement definition, IV `metastatic`). M1 patients whose stage is not Stage IV are set to Stage IV, and Stage X patients that are M0/MX with T4 or N2–N3 count as `locally_advanced` (AJCC). It then drops patients whose category cannot be set, who have no GDC clinical record, or whose histology is NOS, `[Not Available]`, or blank. It also reads the GDC patient and follow-up files to add `recurrence_status` (`none` / `distant` / `locoregional` / `site_unknown` / `unknown`) and drops patients who are not metastatic at diagnosis and have only a new primary tumor. `current_disease_extent` is the answer for `biomarker_record.setting.disease`: metastatic at diagnosis or distant recurrence → `metastatic`; everything else (no recurrence, locoregional recurrence, unknown site or unknown recurrence) keeps the diagnosis category. It also drops currently metastatic patients with no anticancer drug started on or after the metastasis date, and adds `metastasis_dx_days` (0 for stage IV at diagnosis, else the first distant-recurrence day) so the biomarker module can work out lines of therapy itself; the answer set holds no line column. It also adds `locoregional_dx_days` (first locoregional recurrence day) and drops the 4 patients whose combined anthracycline dose records (`+`) cannot be split per drug (listed in `ANTHRACYCLINE_DOSE_UNSPLITTABLE`). The TCGA answer set uses diagnosis-time (primary tumor) stage and receptors only; recurrence receptor columns (`gdc_nte_*`) are kept for reference, and the re-biopsy-first rule (IN-4) applies only to virtual and real charts. It also drops patients with a recurrence of unknown site (`site_unknown`), and patients whose primary HER2 data is unreliable: IHC 2+ (including score-less Equivocal) without a FISH Positive or Negative result unless the IHC call is Positive or Negative, IHC 0 with FISH Positive, or no IHC score with an IHC call other than Positive/Negative and no FISH result. It also drops patients whose PR call is only `Indeterminate` patients with ER, PR, and HER2 (IHC and FISH) all `[Not Evaluated]`, and patients with ER or PR `[Not Evaluated]`, since their receptor or HR status cannot be judged. It then resolves patients whose recurrence status is `unknown`: those not metastatic at diagnosis whose disease-specific survival status is `1:DEAD WITH TUMOR` are dropped, those with recurrence-site receptor values (`gdc_nte_*`) become `locoregional` unless the metastatic tumor indicator is YES without stage IV at diagnosis (dropped), and the rest become `none` (2026-10-20). A negative last follow-up day (`fu_last_days`) has its sign flipped, and patients whose records contradict each other (`UNINTERPRETABLE`) are dropped. The cropped file is the TCGA answer set (860 patients as of 2026-10-20). It splits the ER and PR percent bin `<10%` (primary and recurrence columns): with status `Positive` the bin becomes `1-9%`, and only ER status becomes `Low Positive` (ASCO/CAP defines Low Positive for ER only; PR stays `Positive`); with status `Negative` the bin becomes `<1%` (an assumption, since pre-2010 labs may have used a 10% cutoff). The change log txt lists the patients. It also writes a column description txt and a change log txt. Every merged column must be in either `DROP` or `DESCRIPTIONS`, or the script stops. Run after the merge script.
- `data/metadata/` holds a TCGA-BRCA diagnostic slide list from GDC (v0.2). The script that made it was removed; rewrite it when v0.2 starts.

Input module (A) TCGA conversion: `python -m src.input.script.tcga_to_patient_state` (from `team_project`) turns the cropped CSV into one `patient_state` dict per patient in memory; it writes nothing unless `--out <dir>` is given (`--ids ... --show` prints one). Other code calls `convert(load_rows())`. It is the conversion part of the older `src/input/truth/tcga_truth.py`, which also validates against the schema and writes `data/truth/` plus a report; `data/truth/` was removed on 2026-10-15. The rules are specified in `src/input/tcga_mapping.md`; categorical values come from `data/dictionaries/field_vocab.csv` via `src/input/common/vocab.py`, and the generator stops on any value missing from that file. Every output is validated against `schemas/patient_state.json`. `tests/input/test_tcga_truth.py` checks the output against three expected patients in `tests/input/expected/` and against the counts written in `tcga_mapping.md`; when a rule changes, update the doc, the code, and those counts together.

GDC Biotab files have three header rows (names, alternate names, CDE IDs). Missing values are bracket codes. Keep them: `[Not Available]` means the value was not recorded (maps to 기록 없음), and `[Not Evaluated]` means the test was not done (maps to 미시행).

Module folders (owners and rules in `PROJECT.md` §15):

- `src/input/` [1] input (A), `src/biomarker/` [2] biomarker (B), `src/recommend/` [4] LLM recommendation (B), `src/rag/` [3] guideline RAG and the shared search index (C), `src/reimbursement/` [5] reimbursement auto-update (D). Tests go in the matching `tests/<module>/`.
- Shared folders: `schemas/` (JSON contracts between modules), `llm/` (common LLM interface), `tests/fixtures/` (virtual charts and expected outputs). Change these only after all four members review.
- Write code only inside the module folder you are working on. Modules exchange data only through the `schemas/` formats and do not import each other's internals. The one exception: `src/reimbursement/` calls the index functions that `src/rag/` exposes. Index code lives only in `src/rag/`.

The planned design is in `PROJECT.md` (Korean, design v0.1). Read it before starting work. Summary:

1. Input module: de-identifies pasted chart text, then a local LLM extracts fields with source quotes.
2. Biomarker module: deterministic rules turn reports into status values (e.g. HER2-low). The LLM cannot change them.
3. RAG over ESMO and ASCO guidelines plus HIRA reimbursement notices, filtered by setting, subtype, and line.
4. A local LLM proposes therapy candidates with a reimbursement class, citing chunk ids for every sentence.
5. A reimbursement auto-update module overlays new HIRA notices on the booklet by effective date.
6. An H&E QC module (H-optimus-0 features from TCGA slides) is deferred to v0.2. Work on v0.1 first, starting with TCGA-BRCA clinical and mutation data, not slides.

This is a non-profit project. ESMO guidelines are used under ESMO's non-commercial terms. Do not use NCCN, NICE, or Korean Breast Cancer Society guideline content. Do not use pathology models that need manual access approval (TITAN, UNI, UNI2-h, CONCH, Virchow2). Patient chart text never goes to an external API; only local models see it. Every output item must cite its source document, page or section, and date. Update `PROJECT.md` when items in its "남은 과제" section are decided.

## Environment

- Use a conda env named `team_project` with Python 3.14. Packages in use: `requests`, `pandas`, `tabulate`, `jsonschema`, `pytest`. Install with `conda install -n team_project ...`, not bare `pip`, which may target another env.
- Each member's machine paths, OS, and language preferences belong in their own `CLAUDE.local.md` (git-ignored), not in this file.

## Repository conventions (from .gitignore)

- Inside `data/`, only `.csv`, `.txt`, and `.py` files are committed; everything else there is ignored. To commit another small text format, add `!data/**/*.<ext>` to `.gitignore`. Keep each committed file well under GitHub's 50 MB warning limit. Never commit `*.h5`, `*.db`, `*.parquet`, or `*.npy` files.
- Secrets and API keys go in `.env`, which is ignored.
- `CLAUDE.local.md` is personal and ignored.
- A local virtualenv, if created, should be named `.venv/` (ignored).
