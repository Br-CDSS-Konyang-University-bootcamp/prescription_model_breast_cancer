# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`prescription_model_breast_cancer`: a team Python project for a breast cancer prescription model. The repository is at an early stage. Module code goes in `src/<module>/` with tests in `tests/<module>/` (see PROJECT.md §15). There is no dependency file or lint configuration yet. Tests run with `python -m pytest tests/<module>` from the `team_project` folder.

Shared drug dictionaries: `data/dictionaries/drug_names.csv` (raw name to generic) and `data/dictionaries/drug_classes.csv` (generic to class). `drug_classes.csv` also holds default cycle lengths (`cycle_days`, `cycle_note`) per generic name and a `drug_subclass` (anthracycline, taxane, AI_nonsteroidal, AI_steroidal, LHRH_agonist, SERM, SERD, progestin, CDK4/6_inhibitor, immune_checkpoint_inhibitor) that matches HIRA notice drug-group terms; `data/dictionaries/reimbursement_terms.csv` maps HIRA notice terms to JSON fields and values. `data/metadata/` holds a TCGA-BRCA diagnostic slide list from GDC (v0.2). The script that made it was removed; rewrite it when v0.2 starts. The old TCGA-BRCA download, merge, and crop scripts, their data in `data/tcga_brca/`, and the TCGA-to-`patient_state` converter were removed on 2026-11-18; virtual hospital patients built from TCGA and BCNB are made in `src/virtual_hospital/` with their own copy of the converter and input CSVs (see below).

Guideline RAG (C) scripts, run from `team_project`: `python -m src.rag.convert_pdf_to_md` (guideline PDFs in `data/guidelines/` to `data/parsed_md/`, needs `pymupdf` and `pymupdf4llm`; it maps the PDFs' symbol-font glyphs back to ≥, =, +, –), optionally `python -m src.rag.check_md_quality` to count conversion errors, then `python -m src.rag.chunker_esmo` (writes `data/chunks/esmo_chunks.json`), then `python -m src.rag.algorithm_esmo` (reads the PDFs directly and turns the ESMO treatment algorithm figures into one `chunk_kind: algorithm` chunk per root-to-leaf path in `data/chunks/esmo_algorithm_chunks.json`, from box and arrow coordinates; the EBC 2024 figures draw their text as shapes, so their box text comes from `data/guidelines/esmo_figure_text.csv`; human review status per path is in `data/chunks/esmo_algorithm_review.csv`), then `python -m src.rag.run_indexing`, then `python -m src.rag.evaluate` to score search against the question set `data/eval/rag_eval_cases.csv` (L0 document, L1 section, L2 recall@k and MRR; answers are drafts until `status` is `reviewed`). Reimbursement rows (D's chunks) are found with `src.rag.search_reimbursement(drugs, setting, line, as_of)`: candidate drugs must all be in a row's `drugs`, preview and superseded rows and rows not yet in effect are left out, and parents come from D's chunk file. `src.rag.retrieve_for_recommend(confirmed_state, as_of)` prepares both chunk lists for B's `recommend()` from the doctor-confirmed `schemas/confirmed_state.json` (it reads only `items.*.confirmed`; the older `(patient_state, biomarker_record, as_of)` call still works), and looks for reimbursement rows one line higher when an HIRA deemed-line rule is met; with `with_reimbursement_only=True` it also returns, as a third list, the reimbursement rows of the same setting, line, and subtype that no retrieved guideline drug matched (rows of the current decision's drug class first) (`search_reimbursement_rows`; off-label rows only with `include_offlabel=True`); `python -m src.rag.check_case <confirmed_state.json> [--out data/reimbursement/<name>.json]` prints the real search results for one case (needs both indexes), compares them with the case's `expected/guideline.json` (C's answer file for virtual charts) when it exists, and can save the reimbursement candidates for D, and `src.rag.close_searcher()` releases the local Qdrant lock (it also closes at exit). Guideline PDFs and parsed markdown are copyrighted full texts; never commit them (the repository is public). Where each PDF comes from (both ESMO guidelines are the esmo.org postings, not the Elsevier journal copies), its license basis, and its sha256 are in `data/guidelines/sources.csv`; the converter warns when a PDF's fingerprint differs. `data/dictionaries/guideline_terms.csv` maps patient JSON codes (subtype, setting, line, biomarker `marker:status`, prior drug subclass) to the English phrases the guidelines use, with one `preferred` phrase per value for search queries; `canonical` values are fixed to B's `biomarker_record` values (and A's `patient_state` and drug dictionary values), and C only adds phrases; `python -m src.rag.guideline_terms` shows how many chunks contain each phrase. Chunk `drugs` also lists the drugs of narrow class names written in the guideline text (AI, CDK4/6 inhibitor, taxane, …; `CLASS_TERMS` in `chunk_common.py`); after changing the drug dictionaries or those rules, `python -m src.rag.refresh_drugs` recomputes `drugs` in both guideline chunk files without the PDFs. `tests/rag/test_chunks_schema.py` checks the chunk JSON against `schemas/chunk.json` and for duplicate `chunk_id`s without qdrant.

Input module (A) evaluation uses virtual charts only; the TCGA answer set was dropped on 2026-10-27. Categorical values come from `data/dictionaries/field_vocab.csv` via `src/input/script/rules.py`. The 10 virtual charts in `tests/fixtures/virtual_charts/` (chart text and A's expected `patient_state`) are generated together from case code in `src/input/script/virtual/cases/` by `python -m src.input.script.virtual.virtual_chart` (`--ids VC-0103`, `--check` compares without writing); each value is recorded with its quote position as the text is written, so edit the case code, not the fixture files. Boundary pairs (one value changed from a base case, e.g. `VC-0103-g366`) are defined in `src/input/script/virtual/cases/pairs.py` as parameters to the base case's `build()` and written to `tests/fixtures/virtual_charts/pairs/` with `pairs.json` (expected judgments for B, C, D). `tests/input/test_virtual_charts.py` checks schema, quote positions, and the `lines.annotate` recalculation. The 20 further evaluation cases (VC-0110 to VC-0129, N01 to N20) are listed with their test conditions and draft expected results for B, C, D in `src/input/virtual_patient_cases.md`; `python -m src.input.script.virtual.build_virtual_cases` (`--ids`, `--check`) writes their `chart.txt`, `expected/patient_state.json`, and `scenario.md` (copied from that document's §3) to `tests/fixtures/virtual_charts/<case>/` (next to the first 10) plus `tests/fixtures/virtual_charts/cases.csv`, using the same `Chart` helpers; `tests/input/test_virtual_cases.py` checks every case and that the saved files match. A held-out set of 15 more cases (VC-0130 to VC-0144, N21 to N35, cases where ESMO and HIRA reimbursement disagree or ESMO paths had no case) plus pairs `VC-0111-g20a`, `VC-0111-g20b`, `VC-0115-g21` is listed in `src/input/virtual_patient_cases.md` and generated by `python -m src.input.script.virtual.build_holdout_cases` (`--ids`, `--check`; index `tests/fixtures/virtual_charts/holdout_cases.csv`, test `tests/input/test_holdout_cases.py`); do not look at its wrong cells when changing input rules or prompts, and score it with `python -m src.input.script.evaluation --gold --set holdout`. Expression variants (`python -m src.input.script.virtual.build_variant_cases`, `--check`) rewrite five development cases with only the date format changed (`2021-03-05`, `2021년 3월 5일`, `21/03/05`; the generator's `kdate` reads `virtual_chart.date_style`) into `tests/fixtures/virtual_charts/variants/<case>-<style>/`; values stay the same as the base case (`tests/input/test_variant_cases.py`), and `--set variants` scores them.

Virtual hospital patients (A): `src/virtual_hospital/` builds virtual breast cancer patients from real TCGA-BRCA and BCNB values, filling only missing values by the rules in `data/virtual_hospital/rules/rules.csv` (design and rules: `src/virtual_hospital/README.md`, `notes/build_guide.md`). Run from `team_project`: `python -m src.virtual_hospital.scripts.build` (TCGA post-surgery, `data/virtual_hospital/tcga/`), `.tcga_recur` (TCGA distant recurrence, `data/virtual_hospital/tcga_recur/`), `.bcnb` (BCNB pre-surgery, needs the BCNB download in `data/virtual_hospital/local/bcnb_raw/`), then `.confirmed` (each chart's `expected/confirmed_state.json`, the prescription flow input). It carries its own copy of the TCGA converter (`tcga_convert.py`) and input CSVs (`data/virtual_hospital/source/`). `data/virtual_hospital/` also commits json and md; its `local/` is git-ignored (BCNB license forbids redistributing derived data, plus source ID maps and licensed originals). The actual prescriptions in `truth.csv` are a reference, not gold answers. Tests: `tests/virtual_hospital/test_virtual_hospital.py` (rebuild checks are skipped without `team_project_final`).

Input module (A) chart pipeline entry point: `run(chart_text, extract, patient_ref=..., created_at=...)` in `src/input/script/pipeline.py` returns `(patient_state, issues)`. It splits the original text into documents (`classify.py`, IN-1), masks identifiers with regexes (`deid.py`, IN-0; the mapping stays in memory), passes only the masked documents to `extract` (the IN-2 slot: a function from documents to candidates `{doc_id, field, quote, specimen, observed_date}`, see `candidates.py`), restores and locates each quote in the original text (`quote.py`), normalizes it with `field_vocab.csv` and `drug_names.csv` (`normalize.py`, IN-3), and assembles values, history, conflicts, `not_recorded` defaults, treatment settings, `lines.annotate`, and the schema check (`assemble.py`, IN-4 to IN-7). `issues` lists quotes not found, values not normalized, and schema errors. With `extract` returning the answer's own candidates (`candidates.from_expected`), every virtual chart reproduces its expected `patient_state` except `raw` and conflict notes (`tests/input/test_input_pipeline.py`). `python -m src.input.script.evaluation --gold` scores that run, and `python -m src.input.script.evaluation <dir>` scores saved outputs (`<dir>/<case>/patient_state.json`, optional `issues.json`): field accuracy, status confusion, source position match, and quote rate. The LLM extractor is `src/input/script/pipeline.py` (`make_extract(load_config("extract"))`): one call per document with that document type's field list (enum in the output schema) and one example written outside the test set. Anthracycline doses are computed from medication rows, not asked of the LLM. `python -m src.input.script.pipeline --ids VC-0103 --docs D4` shows one document's candidates against the answer; `--out data/input/runs/<name>` runs the 10 virtual charts end to end and saves `patient_state.json`, `issues.json`, and the LLM's `candidates.json` per case (about an hour on CPU; `data/input/runs/` is git-ignored); `--replay <dir>` re-runs only the rule steps on the saved candidates in seconds.

Screen 1 confirmation values (A): `src/input/script/confirmed.py` builds the `confirmed_state` draft from `patient_state` + `biomarker_record` (`build_draft`; items whose system value is missing or `unknown` stay empty and are listed in `needs`), changes one item (`set_item`, which sets `status` and rejects values the schema does not allow; a changed item needs a `reason`), and saves a new version with `finalize` to `data/input/confirmed/<patient_ref>/v<n>.json` (never overwrites; git-ignored). It also computes `dfi_days`, `high_risk_early`, and `setting.phase` (`adjuvant` when a primary surgery record, pTNM or ypTNM, exists, otherwise `neoadjuvant`; B's `setting.line` is not used). Tests: `tests/input/test_confirmed.py`.

Screens (A, proposed shared folder `src/app/`, pending team review): `python -m src.app.script.screen1 --llm-host http://127.0.0.1:11435` serves screen 1 (confirm prescription conditions) and screen 2 (recommendations and the doctor's choice) on http://127.0.0.1:8501 (standard library only, local only). Pages are in `src/app/html/`. `--cases` takes one or more case folders (e.g. the virtual hospital `data/virtual_hospital/tcga/charts`, `tcga_recur/charts`, `local/bcnb/charts`); cases are keyed by `patient_ref`, and the search box finds a case by chart registration number, virtual ID, or patient name read from the chart's identification line (`App.find`, POST `/api/find`). With `--db` it requests charts from the virtual hospital DB instead (`src/app/script/sources.py` `HospitalDbSource`, calling `src.virtual_hospital.scripts.db`'s `find_patients`/`request_visit`; answer JSON only through `get_answer`). The input selector picks `정답` (the saved answer `patient_state`) or `입력 모듈 LLM` (`Extractor`: runs the chart through `pipeline.run` with the LLM extractor in a background thread, shows "문서 2/4 읽는 중", saves to `data/app/extracted/<patient_ref>/`; same `--llm-host`). With `--records [PATH]` (on by default with `--db`) confirmed versions go to a hospital records SQLite DB (`src/app/script/records.py` `DbStore`, default `data/virtual_hospital/local/hospital_records.db`, kept apart from the rebuilt virtual hospital DB) instead of `data/input/confirmed/` files (`FileStore`); both keep each version's input mode, and screen 2 recommends from that version's input. Screen 1 shows the chart text on the left and, on the right, A (items to resolve: empty required, `unknown`, conflicts), B (rule values, check all), and C (report values, read-only, fix only extraction errors); items that do not apply to the decision are shown locked as not applicable and are not saved. Saving goes to screen 2, which runs C `retrieve_for_recommend` and B `recommend()` with `[recommend]` in the background, shows up to five options sorted by evidence level then reimbursement class, and saves the choice as a `prescription_decision` checked against the draft schema `src/app/prescription_decision.json` (A's proposal `src/app/prescription_decision_proposal.md`, moves to `schemas/` after all four review) to `data/app/decisions/<patient_ref>/v<n>.json`; recommendations are cached in `data/app/recommendations/`. Without `--llm-host` the model is asked on this machine's Ollama; `--llm-host` points at the GPU server through the SSH tunnel (`src/input/py_files.md`). `python -m src.app.script.confirmed_fixtures` (`--ids`, `--check`) writes each virtual chart's gold `expected/confirmed_state.json` (the stage-2 input answer for C `check_case`, D, and B) from its gold `patient_state` + B `assess()` + `build_draft` defaults, as if confirmed on screen 1 with no change; items in a `patient_state` conflict are left empty for the doctor; the hand-made VC-0103 file is kept, and VC-0106b (Ki-67 conflict) and VC-0129 (male, menopausal status not applicable but required by the schema for HR+) are not written. `python -m src.app.script.confirmed_review` (`--check`) compares those files with `tests/fixtures/virtual_charts/confirmed_expectations.csv` (each case's scenario B line and decision point written as item values; a known difference needs a reason in `accepted`) and writes the review sheet `confirmed_review.csv` next to it (one row per case; `status`, `reviewer`, `note` are kept when it is rewritten, and a case counts as gold only once B and C mark it `reviewed`). `python -m src.app.script.run_flow --out data/app/runs/<name> --llm-host http://127.0.0.1:11435` (`--ids`, `--force`, `--summary`) runs screen 2's work (C retrieval, B `recommend()`) for every case with a gold `confirmed_state` without the screens, saves each result as `<out>/<case>/c1.json` (skipped if present), and writes `<out>/summary.csv` comparing citations with C's `expected/guideline.json`; stop the screen server first (Qdrant lock). Tests: `tests/app/`.

Biomarker module (B) entry point: `assess(patient_state)` in `src/biomarker/BM1_ER,PR,HER2,Ki_67,subtype.py` returns one `biomarker_record`; rules are in `src/biomarker/README.md`. LLM recommendation module (B) entry point: `recommend(...)` in `src/recommend/pipeline.py` takes the guideline and reimbursement chunks and an LLM function (prompt text to answer text), and runs the prompt, the hallucination post-processing, and the `schemas/recommendation.json` check; no LLM is connected yet (`src/recommend/README.md`). Tests: `python -m pytest tests/biomarker tests/recommend`.

Reimbursement (D) scripts, run from `team_project`:
- `python -m src.reimbursement.pipeline` checks the HIRA boards, downloads only new files into `data/reimbursement/raw/`, validates the booklet, and writes the reimbursement chunks to `data/reimbursement/chunks/reimbursement_chunks_current.jsonl`.
  - `--offline` uses only files already downloaded.
  - `--no-llm` skips structuring the dosing conditions.
  - `--cross-check` also reads the PDFs with `pdfplumber`.
  - The conditions step tries, in order: a local LLM through Ollama when the `REIMB_OLLAMA_MODEL` environment variable is set (server at `REIMB_OLLAMA_HOST`, default `http://127.0.0.1:11500`, e.g. a GPU server reached by an SSH tunnel; called through `llm/`'s `complete_json`), then the Claude API when `.env` has `ANTHROPIC_API_KEY` with credits, then Claude Code (`claude -p`, after a one-time `/login`). The local LLM (qwen3:32b) writes drafts for new or changed rows only, and people review them (decided 2026-11-02, `PROJECT.md` §14). A row whose text and section context differ from its reviewed previous version only in spacing, punctuation, or its own row number skips the model: code copies the reviewed conditions and realigns the quotes (`carry_over`; the previous contexts come from `chunks/reimbursement_contexts_current.json`, written at each apply). For each row it gets the three most similar reviewed rows as examples, plus the previous version's text and conditions when the row existed in the last chunk file. Code then fixes rule-determined values (`fix_conditions`), and the model is asked once more if the checks fail. `src/reimbursement/verify.py` then checks the draft against the team term dictionary, the numbers in each quote, the 투여대상 text, and a second answer made with other examples. Any phrase that fails goes into `human_review`, so that row is judged unknown. Drafts become reviewed, and usable as examples, only after `--import`. The review sheet lists the least similar new rows first. Results are cached in `data/reimbursement/conditions_cache.jsonl`, so only changed rows are sent again.
  - `python -m src.reimbursement.eval_llm --model MODEL [--limit N] [--shots N] [--think] [--similar N] [--fix] [--previous OLD_CHUNKS.jsonl [--previous-contexts OLD_CONTEXTS.json]]` compares a local model with the reviewed conditions and writes `data/reimbursement/reports/llm_eval_<model>.json` (row ids and numbers only).
  - The off-label (허가초과) list is not used in v0.1 (decided 2026-11-02); its reader stays off unless `--with-offlabel` is given.
  - `python -m src.reimbursement.conditions --import FILE.json` stores hand-written conditions after the same checks.
- `python -m src.reimbursement.index` puts the L3 chunks into the shared index through `src/rag` (`replace_doc_type`: new points first, then only the old reimbursement points not in the new list are removed), so guideline points stay. `--if-changed` (or `pipeline --index`) skips it when the chunks are unchanged since the last index.
- Qdrant local mode allows only one process at a time, so do not run it at the same time as searching or `run_indexing`.
- Packages: `pymupdf`, `jsonschema`, `python-tzdata` (Windows time zones); `pdfplumber` for `--cross-check`; `anthropic` (optional) for the API, until the local LLM replaces it. Indexing also needs `qdrant-client` and `sentence-transformers`.
- HIRA notices say no unauthorized copying, so never commit HIRA originals or anything made from them. That covers the PDFs, chunks, conditions JSON, cache, review sheet, and `registry.db`. Everything under `data/reimbursement/` other than csv, txt, and py is already ignored; keep generated files out of those three formats.

Module folders (owners and rules in `PROJECT.md` §15):

Indexing and search code for both guideline and reimbursement chunks (`search_reimbursement`, `retrieve_for_recommend`) stays in `src/rag/` (C); D writes no index or search code.
- Shared folders: `schemas/` (JSON contracts between modules), `llm/` (common LLM interface), `tests/fixtures/` (virtual charts and expected outputs). Change these only after all four members review.
- Write code only inside the module folder you are working on. Modules exchange data only through the `schemas/` formats and do not import each other's internals. The one exception: `src/reimbursement/` calls the index functions that `src/rag/` exposes. Index code lives only in `src/rag/`.

The planned design is in `PROJECT.md` (Korean, design v0.1). Read it before starting work. Summary:

1. Input module: de-identifies pasted chart text, then a local LLM extracts fields with source quotes.
2. Biomarker module: deterministic rules turn reports into status values (e.g. HER2-low). The LLM cannot change them.
3. RAG over ESMO guidelines plus HIRA reimbursement notices, filtered by setting, subtype, and line.
4. A local LLM proposes therapy candidates with a reimbursement class, citing chunk ids for every sentence.
5. A reimbursement auto-update module overlays new HIRA notices on the booklet by effective date and structures dosing conditions with a local LLM (qwen3:32b writes drafts for new or changed rows; people review them).
6. An H&E QC module (H-optimus-0 features from TCGA slides) is deferred to v0.2. Work on v0.1 first, starting with TCGA-BRCA clinical and mutation data, not slides.

This is a non-profit project. ESMO guidelines are used under ESMO's non-commercial terms. Do not use NCCN, NICE, ASCO treatment guideline (reuse not permitted, checked 2026-10-20), or Korean Breast Cancer Society guideline content. This rule covers the guideline RAG; the biomarker module's ASCO/CAP cutoff references were left unchanged. ## Environment

- Use a conda env named `team_project` with Python 3.14. Packages in use: `requests`, `pandas`, `tabulate`, `jsonschema`, `pytest`, `python-tzdata`; for the guideline RAG `pymupdf`, `pymupdf4llm`; for the shared index `qdrant-client`, `sentence-transformers`; for the reimbursement module `pymupdf`, plus optionally `pdfplumber` and `anthropic`. Install with `conda install -n team_project ...`, not bare `pip`, which may target another env.
- Each member's machine paths, OS, and language preferences belong in their own `CLAUDE.local.md` (git-ignored), not in this file.

## Repository conventions (from .gitignore)

- Inside `data/`, only `.csv`, `.txt`, and `.py` files are committed; everything else there is ignored. To commit another small text format, add `!data/**/*.<ext>` to `.gitignore`. Keep each committed file well under GitHub's 50 MB warning limit. Never commit `*.h5`, `*.db`, `*.parquet`, or `*.npy` files.
- Secrets and API keys go in `.env`, which is ignored.
- `CLAUDE.local.md` is personal and ignored.
- A local virtualenv, if created, should be named `.venv/` (ignored).
