# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`prescription_model_breast_cancer`: a team Python project for a breast cancer prescription model. The repository is at an early stage. Module code goes in `src/<module>/` with tests in `tests/<module>/` (see PROJECT.md §15). TCGA data scripts live in `data/script/`. There is no dependency file or lint configuration yet. Tests run with `python -m pytest tests/<module>` from the `team_project` folder.

TCGA data scripts (run from the `team_project` conda env, from any folder; paths resolve from the script location, with `data/` as the base):

- `data/script/tcga_brca_download.py`: downloads TCGA-BRCA clinical files (GDC BCR Biotab) and cBioPortal PanCancer Atlas clinical, mutation, and biomarker-gene CNA data into `data/tcga_brca/`. Already-downloaded files are skipped.
- `data/script/tcga_brca_explore.py`: prints a structure summary and writes `data/tcga_brca/structure_report.md`. Needs `tabulate`.
- `data/script/tcga_brca_merge.py`: joins all tables on patient ID into one row per patient, `data/tcga_brca/merged/tcga_brca_merged.csv`, plus a column dictionary CSV. Multi-row tables (drugs, radiation, recurrence, follow-up, other cancers, mutations) are summarized per patient. Column prefixes name the source. Run after the download script. Drug names and therapy types are corrected with `data/dictionaries/drug_names.csv` (raw name to generic) and `data/dictionaries/drug_classes.csv` (generic to class). `drug_classes.csv` also holds default cycle lengths (`cycle_days`, `cycle_note`) per generic name, used to estimate `treatment_history[].cycles` when no cycle count is recorded, and a `drug_subclass` (anthracycline, taxane, AI_nonsteroidal, AI_steroidal, LHRH_agonist, SERM, SERD, progestin, CDK4/6_inhibitor, immune_checkpoint_inhibitor) that matches HIRA notice drug-group terms; `data/dictionaries/reimbursement_terms.csv` maps HIRA notice terms to JSON fields and values. The merge stops if a drug name is missing from the dictionary; add it there. Original values stay in `drug_*_raw` columns, and every correction is logged in `merged/drug_corrections.csv`.
- `data/script/tcga_brca_crop.py`: reads the merged CSV (unchanged) and writes `merged/tcga_brca_merging_cropped.csv`, dropping male patients and the columns listed in its `DROP` dict. It first drops patients whose overall stage is `[Discrepancy]`, `[Not Available]`, or blank (the input module's answer-set rule), then adds `stage_disease_extent` (stage I–II `early`, III `locally_advanced` per the HIRA reimbursement definition, IV `metastatic`). M1 patients whose stage is not Stage IV are set to Stage IV, and Stage X patients that are M0/MX with T4 or N2–N3 count as `locally_advanced` (AJCC). It then drops patients whose category cannot be set, who have no GDC clinical record, or whose histology is NOS, `[Not Available]`, or blank. It also reads the GDC patient and follow-up files to add `recurrence_status` (`none` / `distant` / `locoregional` / `site_unknown` / `unknown`) and drops patients who are not metastatic at diagnosis and have only a new primary tumor. `current_disease_extent` is the answer for `biomarker_record.setting.disease`: metastatic at diagnosis or distant recurrence → `metastatic`; everything else (no recurrence, locoregional recurrence, unknown site or unknown recurrence) keeps the diagnosis category. It also drops currently metastatic patients with no anticancer drug started on or after the metastasis date, and adds `metastasis_dx_days` (0 for stage IV at diagnosis, else the first distant-recurrence day) so the biomarker module can work out lines of therapy itself; the answer set holds no line column. It also adds `locoregional_dx_days` (first locoregional recurrence day) and drops the 4 patients whose combined anthracycline dose records (`+`) cannot be split per drug (listed in `ANTHRACYCLINE_DOSE_UNSPLITTABLE`). The TCGA answer set uses diagnosis-time (primary tumor) stage and receptors only; recurrence receptor columns (`gdc_nte_*`) are kept for reference, and the re-biopsy-first rule (IN-4) applies only to virtual and real charts. It also drops patients with a recurrence of unknown site (`site_unknown`), and patients whose primary HER2 data is unreliable: IHC 2+ (including score-less Equivocal) without a FISH Positive or Negative result unless the IHC call is Positive or Negative, IHC 0 with FISH Positive, or no IHC score with an IHC call other than Positive/Negative and no FISH result. It also drops patients whose PR call is only `Indeterminate` patients with ER, PR, and HER2 (IHC and FISH) all `[Not Evaluated]`, and patients with ER or PR `[Not Evaluated]`, since their receptor or HR status cannot be judged. It then resolves patients whose recurrence status is `unknown`: those not metastatic at diagnosis whose disease-specific survival status is `1:DEAD WITH TUMOR` are dropped, those with recurrence-site receptor values (`gdc_nte_*`) become `locoregional` unless the metastatic tumor indicator is YES without stage IV at diagnosis (dropped), and the rest become `none` (2026-10-20). A negative last follow-up day (`fu_last_days`) has its sign flipped, and patients whose records contradict each other (`UNINTERPRETABLE`) are dropped (including drugs that do not fit the subtype), as are patients treated with drugs for a prior breast cancer (GDC `omf` file). Duplicate drug records (same drug and dates) are merged. The cropped file is the TCGA answer set (838 patients as of 2026-10-20). It splits the ER and PR percent bin `<10%` (primary and recurrence columns): with status `Positive` the bin becomes `1-9%`, and only ER status becomes `Low Positive` (ASCO/CAP defines Low Positive for ER only; PR stays `Positive`); with status `Negative` the bin becomes `<1%` (an assumption, since pre-2010 labs may have used a 10% cutoff). The change log txt lists the patients. It also writes a column description txt and a change log txt. Every merged column must be in either `DROP` or `DESCRIPTIONS`, or the script stops. Run after the merge script.
- `data/metadata/` holds a TCGA-BRCA diagnostic slide list from GDC (v0.2). The script that made it was removed; rewrite it when v0.2 starts.

Guideline RAG (C) scripts, run from `team_project`: `python -m src.rag.convert_pdf_to_md` (guideline PDFs in `data/guidelines/` to `data/parsed_md/`, needs `pymupdf` and `pymupdf4llm`; it maps the PDFs' symbol-font glyphs back to ≥, =, +, –), optionally `python -m src.rag.check_md_quality` to count conversion errors, then `python -m src.rag.chunker_esmo` (writes `data/chunks/esmo_chunks.json`), then `python -m src.rag.algorithm_esmo` (reads the PDFs directly and turns the ESMO treatment algorithm figures into one `chunk_kind: algorithm` chunk per root-to-leaf path in `data/chunks/esmo_algorithm_chunks.json`, from box and arrow coordinates; the EBC 2024 figures draw their text as shapes, so their box text comes from `data/guidelines/esmo_figure_text.csv`; human review status per path is in `data/chunks/esmo_algorithm_review.csv`), then `python -m src.rag.run_indexing`, then `python -m src.rag.evaluate` to score search against the question set `data/eval/rag_eval_cases.csv` (L0 document, L1 section, L2 recall@k and MRR; answers are drafts until `status` is `reviewed`). Reimbursement rows (D's chunks) are found with `src.rag.search_reimbursement(drugs, setting, line, as_of)`: candidate drugs must all be in a row's `drugs`, preview and superseded rows and rows not yet in effect are left out, and parents come from D's chunk file. `src.rag.retrieve_for_recommend(confirmed_state, as_of)` prepares both chunk lists for B's `recommend()` from the doctor-confirmed `schemas/confirmed_state.json` (it reads only `items.*.confirmed`; the older `(patient_state, biomarker_record, as_of)` call still works), and looks for reimbursement rows one line higher when an HIRA deemed-line rule is met; with `with_reimbursement_only=True` it also returns, as a third list, the reimbursement rows of the same setting, line, and subtype that no retrieved guideline drug matched (rows of the current decision's drug class first) (`search_reimbursement_rows`; off-label rows only with `include_offlabel=True`); `python -m src.rag.check_case <confirmed_state.json> [--out data/reimbursement/<name>.json]` prints the real search results for one case (needs both indexes), compares them with the case's `expected/guideline.json` (C's answer file for virtual charts) when it exists, and can save the reimbursement candidates for D, and `src.rag.close_searcher()` releases the local Qdrant lock (it also closes at exit). Guideline PDFs and parsed markdown are copyrighted full texts; never commit them (the repository is public). Where each PDF comes from (both ESMO guidelines are the esmo.org postings, not the Elsevier journal copies), its license basis, and its sha256 are in `data/guidelines/sources.csv`; the converter warns when a PDF's fingerprint differs. `data/dictionaries/guideline_terms.csv` maps patient JSON codes (subtype, setting, line, biomarker `marker:status`, prior drug subclass) to the English phrases the guidelines use, with one `preferred` phrase per value for search queries; `canonical` values are fixed to B's `biomarker_record` values (and A's `patient_state` and drug dictionary values), and C only adds phrases; `python -m src.rag.guideline_terms` shows how many chunks contain each phrase. `tests/rag/test_chunks_schema.py` checks the chunk JSON against `schemas/chunk.json` and for duplicate `chunk_id`s without qdrant.

Input module (A) evaluation uses virtual charts only; the TCGA answer set was dropped on 2026-10-27. Only `src/input/script/tcga/tcga_to_patient_state.py` remains, because B's `tests/biomarker/test_bm.py` calls its `convert(load_rows())` (cropped CSV to one `patient_state` per patient, in memory). Categorical values come from `data/dictionaries/field_vocab.csv` via `src/input/script/rules.py`. The 10 virtual charts in `tests/fixtures/virtual_charts/` (chart text and A's expected `patient_state`) are generated together from case code in `src/input/script/virtual/cases/` by `python -m src.input.script.virtual.virtual_chart` (`--ids VC-0103`, `--check` compares without writing); each value is recorded with its quote position as the text is written, so edit the case code, not the fixture files. Boundary pairs (one value changed from a base case, e.g. `VC-0103-g366`) are defined in `src/input/script/virtual/cases/pairs.py` as parameters to the base case's `build()` and written to `tests/fixtures/virtual_charts/pairs/` with `pairs.json` (expected judgments for B, C, D). `tests/input/test_virtual_charts.py` checks schema, quote positions, and the `lines.annotate` recalculation. The 20 further evaluation cases (VC-0110 to VC-0129, N01 to N20) are listed with their test conditions and draft expected results for B, C, D in `src/input/virtual_patient_cases_2026-10-23.md`; `python -m src.input.script.virtual.build_virtual_cases` (`--ids`, `--check`) writes their `chart.txt`, `expected/patient_state.json`, and `scenario.md` (copied from that document's §3) to `tests/fixtures/virtual_charts/<case>/` (next to the first 10) plus `tests/fixtures/virtual_charts/cases.csv`, using the same `Chart` helpers; `tests/input/test_virtual_cases.py` checks every case and that the saved files match. A held-out set of 15 more cases (VC-0130 to VC-0144, N21 to N35, cases where ESMO and HIRA reimbursement disagree or ESMO paths had no case) plus pairs `VC-0111-g20a`, `VC-0111-g20b`, `VC-0115-g21` is listed in `src/input/virtual_patient_cases_2026-10-27.md` and generated by `python -m src.input.script.virtual.build_holdout_cases` (`--ids`, `--check`; index `tests/fixtures/virtual_charts/holdout_cases.csv`, test `tests/input/test_holdout_cases.py`); do not look at its wrong cells when changing input rules or prompts, and score it with `python -m src.input.script.evaluation --gold --set holdout`. Expression variants (`python -m src.input.script.virtual.build_variant_cases`, `--check`) rewrite five development cases with only the date format changed (`2021-03-05`, `2021년 3월 5일`, `21/03/05`; the generator's `kdate` reads `virtual_chart.date_style`) into `tests/fixtures/virtual_charts/variants/<case>-<style>/`; values stay the same as the base case (`tests/input/test_variant_cases.py`), and `--set variants` scores them.

Input module (A) chart pipeline entry point: `run(chart_text, extract, patient_ref=..., created_at=...)` in `src/input/script/pipeline.py` returns `(patient_state, issues)`. It splits the original text into documents (`classify.py`, IN-1), masks identifiers with regexes (`deid.py`, IN-0; the mapping stays in memory), passes only the masked documents to `extract` (the IN-2 slot: a function from documents to candidates `{doc_id, field, quote, specimen, observed_date}`, see `candidates.py`), restores and locates each quote in the original text (`quote.py`), normalizes it with `field_vocab.csv` and `drug_names.csv` (`normalize.py`, IN-3), and assembles values, history, conflicts, `not_recorded` defaults, treatment settings, `lines.annotate`, and the schema check (`assemble.py`, IN-4 to IN-7). `issues` lists quotes not found, values not normalized, and schema errors. With `extract` returning the answer's own candidates (`candidates.from_expected`), every virtual chart reproduces its expected `patient_state` except `raw` and conflict notes (`tests/input/test_input_pipeline.py`). `python -m src.input.script.evaluation --gold` scores that run, and `python -m src.input.script.evaluation <dir>` scores saved outputs (`<dir>/<case>/patient_state.json`, optional `issues.json`): field accuracy, status confusion, source position match, and quote rate. The LLM extractor is `src/input/script/pipeline.py` (`make_extract(load_config("extract"))`): one call per document with that document type's field list (enum in the output schema) and one example written outside the test set. Anthracycline doses are computed from medication rows, not asked of the LLM. `python -m src.input.script.pipeline --ids VC-0103 --docs D4` shows one document's candidates against the answer; `--out data/input/runs/<name>` runs the 10 virtual charts end to end and saves `patient_state.json`, `issues.json`, and the LLM's `candidates.json` per case (about an hour on CPU; `data/input/runs/` is git-ignored); `--replay <dir>` re-runs only the rule steps on the saved candidates in seconds.

Biomarker module (B) entry point: `assess(patient_state)` in `src/biomarker/BM1_ER,PR,HER2,Ki_67,subtype.py` returns one `biomarker_record`; rules are in `src/biomarker/README.md`. LLM recommendation module (B) entry point: `recommend(...)` in `src/recommend/pipeline.py` takes the guideline and reimbursement chunks and an LLM function (prompt text to answer text), and runs the prompt, the hallucination post-processing, and the `schemas/recommendation.json` check; no LLM is connected yet (`src/recommend/README.md`). Tests: `python -m pytest tests/biomarker tests/recommend`.

Reimbursement (D) scripts, run from `team_project`:
- `python -m src.reimbursement.pipeline` checks the HIRA boards, downloads only new files into `data/reimbursement/raw/`, validates the booklet, and writes the reimbursement chunks to `data/reimbursement/chunks/reimbursement_chunks_current.jsonl`.
  - `--offline` uses only files already downloaded.
  - `--no-llm` skips structuring the dosing conditions.
  - `--cross-check` also reads the PDFs with `pdfplumber`.
  - The conditions step is to move to a local LLM (decided 2026-10-23; model not chosen yet, see `PROJECT.md` §9 and §14). Until that is built, the code uses the Claude API when `.env` has `ANTHROPIC_API_KEY` with credits, and otherwise falls back to Claude Code (`claude -p`, after a one-time `/login`). Results are cached in `data/reimbursement/conditions_cache.jsonl`, so only changed rows are sent again.
  - `python -m src.reimbursement.conditions --import FILE.json` stores hand-written conditions after the same checks.
- `python -m src.reimbursement.index` puts the L3 chunks into the shared index through `src/rag`. It removes only `doc_type=reimbursement` points, so guideline points stay.
- Qdrant local mode allows only one process at a time, so do not run it at the same time as searching or `run_indexing`.
- Packages: `pymupdf`, `jsonschema`, `python-tzdata` (Windows time zones); `pdfplumber` for `--cross-check`; `anthropic` (optional) for the API, until the local LLM replaces it. Indexing also needs `qdrant-client` and `sentence-transformers`.
- HIRA notices say no unauthorized copying, so never commit HIRA originals or anything made from them. That covers the PDFs, chunks, conditions JSON, cache, review sheet, and `registry.db`. Everything under `data/reimbursement/` other than csv, txt, and py is already ignored; keep generated files out of those three formats.

GDC Biotab files have three header rows (names, alternate names, CDE IDs). Missing values are bracket codes. Keep them: `[Not Available]` means the value was not recorded (maps to 기록 없음), and `[Not Evaluated]` means the test was not done (maps to 미시행).

Module folders (owners and rules in `PROJECT.md` §15):

- `src/input/` [1] input (A), `src/biomarker/` [2] biomarker (B), `src/recommend/` [4] LLM recommendation (B), `src/rag/` [3] guideline RAG and the shared search index (C), `src/reimbursement/` [5] reimbursement auto-update (D). Tests go in the matching `tests/<module>/`.
- Chunks are split by source (2026-10-23): C makes the ESMO guideline chunks and their format; D makes the HIRA reimbursement chunks and their format (the `reimbursement` field of `schemas/chunk.json`). Indexing and search code for both guideline and reimbursement chunks (`search_reimbursement`, `retrieve_for_recommend`) stays in `src/rag/` (C); D writes no index or search code.
- Shared folders: `schemas/` (JSON contracts between modules), `llm/` (common LLM interface), `tests/fixtures/` (virtual charts and expected outputs). Change these only after all four members review.
- Write code only inside the module folder you are working on. Modules exchange data only through the `schemas/` formats and do not import each other's internals. The one exception: `src/reimbursement/` calls the index functions that `src/rag/` exposes. Index code lives only in `src/rag/`.

The planned design is in `PROJECT.md` (Korean, design v0.1). Read it before starting work. Summary:

1. Input module: de-identifies pasted chart text, then a local LLM extracts fields with source quotes.
2. Biomarker module: deterministic rules turn reports into status values (e.g. HER2-low). The LLM cannot change them.
3. RAG over ESMO guidelines plus HIRA reimbursement notices, filtered by setting, subtype, and line.
4. A local LLM proposes therapy candidates with a reimbursement class, citing chunk ids for every sentence.
5. A reimbursement auto-update module overlays new HIRA notices on the booklet by effective date and structures dosing conditions with a local LLM (model not chosen yet).
6. An H&E QC module (H-optimus-0 features from TCGA slides) is deferred to v0.2. Work on v0.1 first, starting with TCGA-BRCA clinical and mutation data, not slides.

This is a non-profit project. ESMO guidelines are used under ESMO's non-commercial terms. Do not use NCCN, NICE, ASCO treatment guideline (reuse not permitted, checked 2026-10-20), or Korean Breast Cancer Society guideline content. This rule covers the guideline RAG; the biomarker module's ASCO/CAP cutoff references were left unchanged. Do not use pathology models that need manual access approval (TITAN, UNI, UNI2-h, CONCH, Virchow2). Patient chart text never goes to an external API; only local models see it. Every output item must cite its source document, page or section, and date. Update `PROJECT.md` when items in its "남은 과제" section are decided.

## Environment

- Use a conda env named `team_project` with Python 3.14. Packages in use: `requests`, `pandas`, `tabulate`, `jsonschema`, `pytest`, `python-tzdata`; for the guideline RAG `pymupdf`, `pymupdf4llm`; for the shared index `qdrant-client`, `sentence-transformers`; for the reimbursement module `pymupdf`, plus optionally `pdfplumber` and `anthropic`. Install with `conda install -n team_project ...`, not bare `pip`, which may target another env.
- Each member's machine paths, OS, and language preferences belong in their own `CLAUDE.local.md` (git-ignored), not in this file.

## Repository conventions (from .gitignore)

- Inside `data/`, only `.csv`, `.txt`, and `.py` files are committed; everything else there is ignored. To commit another small text format, add `!data/**/*.<ext>` to `.gitignore`. Keep each committed file well under GitHub's 50 MB warning limit. Never commit `*.h5`, `*.db`, `*.parquet`, or `*.npy` files.
- Secrets and API keys go in `.env`, which is ignored.
- `CLAUDE.local.md` is personal and ignored.
- A local virtualenv, if created, should be named `.venv/` (ignored).
